## WebAssembly (Wasm) - Состояние на 2025-2026
- **Безопасность**: Раньше можно было разрешить небезопасный JavaScript, теперь только WebAssembly. Это значительно повышает безопасность.
- **Стандартизация**: Процесс стандартизации сейчас активно идет.
- **Поддержка**: Появилась поддержка 128-битных целых чисел (если вдруг понадобится).
### WebAssembly - Версии
- 2017 год: Вышла версия 1.0 (MVP).
- 2022 год: Вышла версия 2.0.
- 2025 год: Вышла версия 3.0.
### WebAssembly 3.0 - Основные улучшения
- Поддержка исключений.
- Сборка мусора (Garbage Collection).
- 64-битная память.
- SIMD (Single Instruction Multiple Data).
- Tail call оптимизации.
### .NET 10 и WebAssembly
- Начали с .NET 10 (ноябрь 2025).
- Улучшилась производительность и стабильность.
- Значительно улучшилась диагностика (в контексте Blazor).
- Улучшена диагностика JavaScript Interop, интегрировано с браузерными DevTools. Стало лучше.
- Отладка WebAssembly теперь возможна прямо из IDE, без необходимости в браузерных DevTools, через специальный прокси.
- В одном из последних подкастов рассказывали про новую фичу под названием Performance Profiling Diagnostics Extraction: позволяет профилировать WebAssembly прямо в браузере.
- Платформа .NET также развивается в ранней версии 2025 года, версия 5.6.
- Сделали AOT (Ahead-of-Time) компиляцию.
### .NET 10 и WebAssembly - Улучшения и Коллаборация
- AOT компиляция позволяет ускорить работу в 10 раз.
- В октябре сделали улучшения в обработке изображений.
- В ноябре вышел релиз на основе .NET 10.
- .NET сильно заколлаборировался с Microsoft.
- Microsoft контрибьютит в .NET.
- Microsoft собирается контрибьютить в Maui.
- Microsoft собирается контрибьютить в поддержку многопоточности в Maui.
### .NET 11 и WebAssembly - Планы
- В .NET 11 не ожидается много улучшений в WebAssembly.
- Идет переход от моно-тайма к курсиву.
### .NET 12 и WebAssembly
- В .NET 12 планируется большая интеграция с WebAssembly.
- .NET 12 будет поддерживать сборку мусора (Garbage Collection) и 64-битную память в WebAssembly.
- WebAssembly 3.0 уже сейчас является практически оформленным стандартом.
### WASI (WebAssembly System Interface)
- Это стандартизированный протокол для WebAssembly.
- Позволяет писать модули, которые могут взаимодействовать с операционной системой.
- WASI пока до версии 0.3, планируется до версии 1.0 к концу 2026 или началу 2027. Сейчас WebAssembly можно использовать вне браузера, например, для написания плагинов.
- .NET не сильно светится в контексте WASI, так как это скорее стандарт, чем специфика .NET.
- Решено добавить WASI для полноценности.
- Статистика по Chrome: 5.5% сайтов, посещаемых через Chrome, используют WebAssembly. Это по данным Google.
- Рост использования WebAssembly: примерно 1% в год.
- WebAssembly не стремится захватить весь интернет.
- Юзкейсы: IoT (интернет вещей), где мало памяти и нет возможности запускать большие приложения.
### WebAssembly - Поддержка Языков
- Почти все из топ 25 языков программирования поддерживают WebAssembly в той или иной форме.
- Даже некомпилируемые языки, такие как SQL, поддерживают WebAssembly в формате хранимых процедур.
- WebAssembly позволяет писать user-defined functions, которые можно использовать в запросах.
- WebAssembly - удобный стандарт для плагинов.
- Если приложение раньше думало, на каком языке предоставить плагины, то WebAssembly - универсальное решение.
- Планы на 2026 год: .NET, скорее всего, не будет сильно рваться вперед и .NET нужно перейти на плюс-минус один runtime, чтобы не делать дважды одну и ту же работу.
### WebAssembly - Планы на будущее
- Планируется стандартизировать Content Security Policy (CSP) для WebAssembly.
- Ожидается поддержка 128-битных целых чисел и SIMD в Safari.
- Большая работа планируется по интеграции с JavaScript модулями.
- Сейчас для использования WebAssembly из JavaScript необходимо отдельно загружать WebAssembly модуль.
- Это требует явной загрузки модуля, как если бы в C# использовали `Activator.CreateInstance`.
### WebAssembly - Планы на будущее
- Сейчас идет первая фаза, так называемый `Source Phase Import` (Stage 3), чтобы загрузка модулей была более прозрачной.
- Chrome и Firefox активно работают над этим, ожидается, что будет доступно для тестирования к 2026 году.
- Конечная цель — сделать импорт WebAssembly модулей таким же простым, как импорт JavaScript модулей.

Состояние WebAssembly выглядит многообещающим, ждем улучшений в .NET 12. Сейчас фокус на поддержке многопоточности. Важно, чтобы вклад в развитие WebAssembly вносила не только команда Microsoft, но и более широкое сообщество. WebAssembly - это хорошая технология, и хотя пока неясно, насколько он оправдан хайпом, это многообещающий путь.
