## WebAssembly (Wasm) - Состояние на 2025-2026
- **Безопасность**: Раньше можно было разрешить небезопасный JavaScript, теперь только WebAssembly. Это значительно повышает безопасность.
- **Стандартизация**: Процесс стандартизации сейчас активно идет.
- **Поддержка**: Появилась поддержка 128-битных целых чисел (если вдруг понадобится).
### WebAssembly - Версии
- 2017 год: Вышла версия 1.0 (MVP).
- 2022 год: Вышла версия 2.0.
- 2025 год: Вышла версия 3.0.
### WebAssembly 3.0 - Основные улучшения
- Поддержка исключений.
- Сборка мусора (Garbage Collection).
- 64-битная память.
- SIMD (Single Instruction Multiple Data).
- Tail call оптимизации.
### .NET 10 и WebAssembly
- Начали с .NET 10 (ноябрь 2025).
- Улучшилась производительность и стабильность.
- Значительно улучшилась диагностика (в контексте Blazor).
- Улучшена диагностика JavaScript Interop, интегрировано с браузерными DevTools. Стало лучше.
- Отладка WebAssembly теперь возможна прямо из IDE, без необходимости в браузерных DevTools, через специальный прокси.
- В одном из последних подкастов рассказывали про новую фичу под названием Performance Profiling Diagnostics Extraction: позволяет профилировать WebAssembly прямо в браузере.
- Платформа .NET также развивается в ранней версии 2025 года, версия 5.6.
- Сделали AOT (Ahead-of-Time) компиляцию.
### .NET 10 и WebAssembly - Улучшения и Коллаборация
- AOT компиляция позволяет ускорить работу в 10 раз.
- В октябре сделали улучшения в обработке изображений.
- В ноябре вышел релиз на основе .NET 10.
- .NET сильно заколлаборировался с Microsoft.
- Microsoft контрибьютит в .NET.
- Microsoft собирается контрибьютить в Maui.
- Microsoft собирается контрибьютить в поддержку многопоточности в Maui.
### .NET 11 и WebAssembly - Планы
- В .NET 11 не ожидается много улучшений в WebAssembly.
- Идет переход от моно-тайма к курсиву.
### .NET 12 и WebAssembly
- В .NET 12 планируется большая интеграция с WebAssembly.
- .NET 12 будет поддерживать сборку мусора (Garbage Collection) и 64-битную память в WebAssembly.
- WebAssembly 3.0 уже сейчас является практически оформленным стандартом.
### WASI (WebAssembly System Interface)
- Это стандартизированный протокол для WebAssembly.
- Позволяет писать модули, которые могут взаимодействовать с операционной системой.
- WASI пока до версии 0.3, планируется до версии 1.0 к концу 2026 или началу 2027. Сейчас WebAssembly можно использовать вне браузера, например, для написания плагинов.
- .NET не сильно светится в контексте WASI, так как это скорее стандарт, чем специфика .NET.
- Решено добавить WASI для полноценности.
- Статистика по Chrome: 5.5% сайтов, посещаемых через Chrome, используют WebAssembly. Это по данным Google.
- Рост использования WebAssembly: примерно 1% в год.
- WebAssembly не стремится захватить весь интернет.
- Юзкейсы: IoT (интернет вещей), где мало памяти и нет возможности запускать большие приложения.
### WebAssembly - Поддержка Языков
- Почти все из топ 25 языков программирования поддерживают WebAssembly в той или иной форме.
- Даже некомпилируемые языки, такие как SQL, поддерживают WebAssembly в формате хранимых процедур.
- WebAssembly позволяет писать user-defined functions, которые можно использовать в запросах.
- WebAssembly - удобный стандарт для плагинов.
- Если приложение раньше думало, на каком языке предоставить плагины, то WebAssembly - универсальное решение.
- Планы на 2026 год: .NET, скорее всего, не будет сильно рваться вперед и .NET нужно перейти на плюс-минус один runtime, чтобы не делать дважды одну и ту же работу.
### WebAssembly - Планы на будущее
- Планируется стандартизировать Content Security Policy (CSP) для WebAssembly.
- Ожидается поддержка 128-битных целых чисел и SIMD в Safari.
- Большая работа планируется по интеграции с JavaScript модулями.
- Сейчас для использования WebAssembly из JavaScript необходимо отдельно загружать WebAssembly модуль.
- Это требует явной загрузки модуля, как если бы в C# использовали `Activator.CreateInstance`.
### WebAssembly - Планы на будущее
- Сейчас идет первая фаза, так называемый `Source Phase Import` (Stage 3), чтобы загрузка модулей была более прозрачной.
- Chrome и Firefox активно работают над этим, ожидается, что будет доступно для тестирования к 2026 году.
- Конечная цель — сделать импорт WebAssembly модулей таким же простым, как импорт JavaScript модулей.

### Веб-фреймворки
- В .NET, если Microsoft что-то написала, то обычно это хорошо и работает.
- Если есть ASP.NET, не очень понятно, зачем нужно что-то другое, поэтому никто другого ничего не использует.
- Есть альтернативные веб-фреймворки, их много.
- Автор статьи собрал самые популярные из них и решил показать, что альтернативы существуют. Она есть и, может быть, она нужна, так как вы об этом не знаете.
### Веб-фреймворки в .NET - Продолжение
- ASP.NET Core базируется на библиотеке `libuv`.
- Движок ASP.NET Core называется `Kestrel`.
- Для написания API есть два основных подхода:
    - `Controller-based API` (на основе контроллеров)
    - `Minimal API`
- Поддерживаются различные стили API.
- Есть богатый набор `middleware` для реализации функционала, такого как сжатие, кэширование, аутентификация и прочее.
- Нативная поддержка `HTTP/3`.
### Веб-фреймворки в .NET - Альтернативы ASP.NET
- ASP.NET Core - это хороший и мощный веб-сервер.
- Существуют альтернативы, например `Gen HTTP`.
- `Gen HTTP` разрабатывается с 2008 года, в 2019 году был пересмотрен.
- ASP.NET Core базируется на библиотеке `libuv`, движок `Kestrel`.
- Для API есть `Controller-based API` и `Minimal API`.
- Поддерживает `HTTP/3`.
- Большой набор `middleware`.
### Gen HTTP
- Разрабатывается с 2008 года, пересмотрен в 2019.
- Предоставляет больше гибкости, чем ASP.NET.
- Подходит, если нужен более гибкий и мелкий фреймворк, чем ASP.NET.
- Имеет встроенные: `reverse proxy`, `server-side caching`, и `MTLS`.
- Opensource (как и большинство обозреваемых фреймворков).
- Есть коммерческая лицензия, на которой зарабатывают.
- HTTP нужен разработчикам, если вы хотите большей гибкости.
### Sisk
- Разрабатывается с 2022 года.
- Требует .NET 8 или старше.
- Ориентирован на декларативный язык описания.
- Минимальное количество зависимостей.
- Хорошая документация, понятная и полная.
- Поддерживает только HTTP 1.1, включая WebSockets и Server-Sent Events.
- Хорош для минималистичных решений.
- Очень простой, маленький, прямой и понятный.
- Ориентирован на декларативное программирование.
### SimpleW (Simple Web) - Веб-фреймворк
- Разработка началась в 2023 году. Довольно новый фреймворк.
- Поддерживает `Controller-style API` (API на основе контроллеров).
- Предназначен для создания API, если нужен более легковесный и простой вариант.
- Он активен и активно развивается, что говорит о его востребованности.
### Enhancel HTTP
- Альтернативный веб-фреймворк.
- Controller-based API, то есть endpoints пишутся с помощью контроллеров.
- Поддерживает Websockets, Server-Sent Events и HTTP 1.1.
- По производительности обгоняет Minimal API из ASP.NET Core.
- Подходит, если нужен Controller-based API и высокая производительность.
### SimpleW (Simple Web) - Веб-фреймворк
- Поддерживает **только HTTP 1.1** (включая WebSockets и Server-Sent Events).
- Основная задача этого фреймворка — показать, насколько быстрым может быть .NET для протокола HTTP 1.1.
- В бенчмарках TechEmpower этот сервер занимает **четвертое место**, достигая 98.4% производительности лидера.
- **Важно:** Этот сервер не предназначен для использования в продакшене, его цель — демонстрация высокой производительности.
### Watson - Веб-фреймворк
- Специальный веб-фреймворк с низкоуровневым доступом к HTTP-примитивам.
- Поддерживает большое количество фреймворков: от .NET 4.6.1 и .NET Standard 2.1 до последних версий .NET 10.
- Хороший выбор, если нужна гибкость и поддержка различных версий .NET.
### Wired.IO - Веб-фреймворк
- Разработка началась в 2024 году. Это самый молодой фреймворк из списка.
- Из коробки поддерживает `Dependency Injection` и `Logging`.
- Предоставляет полный контроль над HTTP.
- Watson - специальный веб-фреймворк с низкоуровневым доступом к HTTP-примитивам.
- Позволяет подменить стандартный HTTP-парсер на свой.
- Можно напрямую писать в HTTP response.
- Много низкоуровневых трюков.
- Хорошая документация.
- Endpoint'ы быстрее, чем у Minimal API ASP.NET.
- Подходит для сложных сценариев, где нужна тонкая настройка.
- Довольно производителен.
### Веб-фреймворки - Активные и Неактивные
- **Активные**: Фреймворки, которые активно разрабатываются и в которые вносятся улучшения.
- **Неактивные**: Фреймворки, которые не поддерживаются или разрабатываются неактивно.
- Enhanced HTTP позволяет очень хорошо контролировать входящие и исходящие HTTP-стримы.
- Enhanced HTTP довольно гибкий и кастомизируемый.
- Enhanced HTTP может состязаться с ASP.NET в определенных задачах.
- **Неактивные фреймворки**: EmbeddedIO, NetCoreServer, Nancy.
- Nancy упоминали в подкасте, когда .NET Core только начинался.
### Nancy - Веб-фреймворк
- Nancy был глотком свежего воздуха для .NET разработчиков.
- Nancy - это достойная конкуренция ASP.NET.
- Minimal API в ASP.NET Core во многом вдохновлен Nancy.
- Nancy больше не развивается, проект заархивирован.
### Веб-фреймворки - Альтернативы ASP.NET - Зачем?
- Новые подходы и идеи из других языков.
- Новые способы задания endpoint'ов, настроек и конфигураций.
- Новизна - это хорошо, не нужно замыкаться на одном большом и негибком фреймворке.
- ASP.NET Core - производительный сервер, но общего назначения.
- В некоторых узких местах производительность сторонних веб-серверов может быть выше.
### Веб-фреймворки - Когда использовать альтернативы ASP.NET Core?
- Если вам нужен маленький, встраиваемый веб-сервис.
- ASP.NET Core может быть избыточным для встраиваемых решений (например, в десктопные приложения или игры на Unity).
- Если нужно низкоуровневое управление потоками, протоколами, битиками и байтиками для реализации собственных протоколов или максимизации производительности.
### Веб-фреймворки - Зачем они нужны?
- Другие фреймворки раскрывают доступ к сокетам и стримам на низком уровне.
- Позволяют обходить стандартные механизмы.
- Другие сервера раскрывают необходимые уровни для настройки и взаимодействия на удобном уровне.
- Веб-сервер — один из самых популярных запросов для изучения.
- Написание собственного веб-сервера.
- Изучение работы HTTP протокола на низком уровне.
- Обучение на альтернативах полезно, потому что ASP.NET огромный и сложный для изучения. И хочется чего-то более мелкого, простого и понятного. Возможно, с хорошей документацией.
- Альтернативные фреймворки предоставляют такую возможность. Они пользуются своей популярностью и востребованы в некоторых нишах.
- В реальной жизни они используются реже, чем ASP.NET.
### Software Bill of Materials (SBOM) или СБОМ
- На русском: "Перечень зависимостей".
- SBOM важен, потому что показывает, откуда мы берем код, и как он используется.
### Software Bill of Materials (SBOM) или СБОМ - Продолжение
- Это как ведомость материалов, но для софта.
- Показывает, из чего состоит программное обеспечение, какие компоненты используются.
### Software Bill of Materials (SBOM) - Применение
- SBOM включает в себя все пакеты, зависимости и компоненты, необходимые для создания программного обеспечения.
- **Задачи, которые позволяет решить SBOM:**
    - Определение потенциальных уязвимостей в компонентах и зависимостях.
    - Проверка лицензионной чистоты, чтобы избежать использования GPL-зависимостей.
### Software Bill of Materials (SBOM) - Стандарты и Форматы
- Для SBOM существуют два основных стандарта:
    - SPDX
    - CycloneDX
- Эти стандарты являются ISO/IEC стандартами.
- Данные в этих стандартах обычно хранятся в формате JSON.
